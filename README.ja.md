# Galmuri · 갈무리

**複数のプロファイルのブックマークを一か所で整理し、ブラウザに反映。**

[English](README.md) · [한국어](README.ko.md) · 日本語 · [简体中文](README.zh-Hans.md)

Galmuriは開発中の **SwiftUI製ネイティブmacOSブックマークエディタ**です。複数のChromeプロファイルを永続的な作業コピーとして取り込み、アプリでの編集と最新の原本をマージして確認します。既存のファイル方式の作業コピーに拡張機能は不要です。任意のプロファイル別拡張ブリッジで実行中のChromeモデルを読み取り、永続的な編集、3-wayレビュー、明示的に有効化した専用テスト環境での復元可能な反映を行えます。

## 現在の状態

設定 → 実験室 → API接続とエディタでAPI操作とプロファイルの承認を行います。拡張機能のインストール案内から対応するZIPを保存でき、`Bridge/extension`には将来のGitHubダウンロード用Releaseフォルダを用意しています。ファイル直接反映も実験室に移し、アプリ所有の合成テストファイルのみ対応します。Chromeの終了で自動反映はしません。[実験室とインストール](docs/labs.md)を参照してください。拡張機能は`bookmarks`、`nativeMessaging`、`storage`権限を使い、ウェブサイト権限はありません。通常の接続はChromeに対して読み取り専用で、明示的なマーカーのある専用テスト接続のみ反映できます。作成・名前変更・移動・並べ替え、復旧フォルダへの削除、確認後の復元、中断状態の採用、ブラウザ再起動を専用Chrome for Testingで確認しました。[APIの設定・動作・制限](docs/chrome-api-workspace.md)を参照してください。

Release27では大きな進捗・結果の転送を修正し、中止確認と現在状態の復旧、戻る・進む・上へ、複数選択とドラッグ先を追加しました。落ち着いたグレーの画面と青い操作・選択表示に整理しました。Coreマージの測定と制限は[ネイティブ改善](docs/native-refinement.md)を参照してください。実ユーザーへの書き込み、実機のアクセシビリティ、実際のChrome設定・同期の検証は引き続き制限しています。

Release28では削除予定項目とフォルダ内容の変更も反映前の変更一覧に表示し、確認後に復元できます。接続情報は別のシートで開き、保存済みの編集内容と作業コピーの互換性を維持します。

Release30では実験室の2機能を個別にオン・オフでき、初期値はオフです。API編集を有効にすると選択中のプロファイルのディスク上の拡張機能記録を確認し、動作・接続とは区別します。変更の確認は保存済み元データと作業コピーを比較し、再読込マージとは別です。オフにしても編集を保持し、実プロファイルへの書き込み制限も維持します。

Release31ではメインサイドバーと初期接続画面に設定ボタンを追加し、設定内を一般・実験室に分けました。API編集をオンにするとGalmuri登録済みの全プロファイルを一度確認し、その後は手動で再確認します。記録と確認時刻を表示し、エディタの選択変更では自動再検査しません。未登録プロファイルを検索せず、記録と動作・接続を区別します。

Release32ではコード全体の点検結果を反映しました。HTML書き出しはhttp(s)以外のアドレスをスキップして件数を表示し、そのようなブックマークも名前を変更できます。API編集は変更したアドレスを正規化し、表示順どおりに移動し、復元記録を1件だけ保持します。セッション期限の直前には反映を開始せず、完了したジョブファイルを削除します。編集のたびに全ての元データを読み直さず、変化のない編集は保存しません。取り消しは100段階まで、「更新前」の保管コピーは最新10件のみ残します。「接続解除」と「読み込み前」の保管コピーは自動では削除しません。

Release33では点検の残作業を完了しました。確認時の読み込み・統合・反映・復元はメインスレッド外で実行され、実行中にシートを閉じて中断することはできず、復元は実際に完了したかを表示します。API編集は変更したアドレスを国際ドメイン名を含めてChromeと同じ形で保存し、Chromeが書き換えるアドレスは拒否します。セッション残り時間が2分未満の場合や保存済みアドレスがChromeの形でない場合は、反映を最初から拒否します。未接続の暗号化ストア実験コードを削除し、メイン表はAppKitの再入警告を出さなくなりました。

ネイティブアプリのローカル開発を進めています。サイドバーと表、入れ子のフォルダ、ブックマーク編集、複数選択での移動・同じプロファイル内のドラッグ移動、並べ替え、検索、同じURLの表示、除外・取り消し、作業コピーのJSONバックアップと読み込み、全体・フォルダ配下のNetscape HTML出力を実装しています。Swiftの実際の3-wayマージ結果を使い、競合の選択と最終確認を行います。原本のバックアップ・置換・復元は、現在 **アプリが作成した合成テストファイルのみ** に許可しています。

ファイル方式で接続した外部Chromeプロファイルの原本は読み取り専用です。フォルダへのアクセスを失っても作業コピーは編集でき、元のフォルダを再選択すると編集を初期化せずにアクセスを復旧できます。反映・復元の承認は原本のバイト列とファイル識別情報に結び付き、破損した記録があっても有効なバックアップは表示されます。**暗号化されたブックマークへの対応は保留しました。** 設定 → 実験室にはオフの無効な「対応予定」項目のみを表示し、キーチェーンへのアクセスや暗号化ストアのアプリ統合は実装しません。アプリから切り離したコア実験のソースは2026-11-12に削除しました。[過去の検証記録](docs/encrypted-store-adapter.md)はそのまま保持します。この実験はアプリの対応機能ではありませんでした。外部ファイルへの直接書き込みは無効のままで、上記のAPIテストによって有効にはなりません。平文ストアの権限・ブラウザ終了確認、ブラウザへの反映・同期、ネイティブのアクセシビリティ・言語、配布の検証は未完了です。直接反映が製品の目標であり、HTML出力で代替しません。同じURLの項目も別々に保持します。

新しいワークスペースはブラウザへの接続画面で起動します。Chromeへの接続時に標準の場所への通常のアクセスを試し、許可されていればプロファイル名を直接表示します。権限や別の保存場所が必要な場合のみ、アプリ内の案内からフォルダを選択します。選択した対応プロファイルのみ追加します。以前のテストプロファイルと編集内容は保持され、明示的に開くことができます。編集・移動・削除ボタン、各行の鉛筆ボタン、取り消しを表示します。単一ブックマークの削除はすぐに取り消せ、フォルダや複数項目の削除は対象と全体の影響を先に確認できます。[編集UXの決定](docs/editing-ux.md)を参照してください。

GitHub公開と一般リリースはローカル確認後に行います。[TASKS.md](TASKS.md)に進捗とブロッカー、[検証記録](docs/validation.md)に根拠と制限を記載しています。

接続画面でChromeまたはEgo Liteを選ぶと、そのブラウザの標準の場所を検索します。Ego Liteは平文ブックマークに限定した試験的な読み取り専用接続で、最新状態や実際のブラウザとの互換性は未検証です。フォルダ選択は権限や別の場所が必要な場合の補助手段であり、macOSによる承認が必要なことがあります。

ブラウザへのアクセスが拒否された場合は、まずフォルダの許可を案内します。標準の選択画面でデータフォルダを開くので、場所を変更せず「このフォルダへのアクセスを許可」を押します。確認後にプロファイル情報を読み取り、成功時のみ進みます。該当するmacOSのChromeで選択したフォルダも拒否された場合にシステム設定を案内し、通常のファイル権限エラーは別に扱います。既存の作業は保持します。実際の保護フォルダの承認と権限の持続は未検証です。

ポインタは動くもののクリックとキー入力に反応しなかったとの報告を受け、設定項目の自動検索を撤回しました。Release 17でアクセシビリティの実装と権限要求を削除し、この方式は再導入しません。設定案内のボタンは「ファイルとフォルダ」を開くのみで、Galmuriを手動で探して展開します。接続に追加のアクセシビリティ・オートメーション権限は不要です。症状の原因は未確定です。

プロファイル選択画面で検出したブックマークファイルと更新日時を確認できます。暗号化・別ストアのファイルがあっても、読み取り可能な平文Bookmarksは選択でき、他の内容は除外します。平文ファイルなしと読み取り不可を分けて理由を表示します。種類は名前による分類で、更新日時はChromeの最新内容を保証しません。選択した平文は取り込み時に検証し、原本への書き込み制限は維持します。

## ローカル実行

macOS、Xcodeコマンドラインツール、Swift 6以降が必要です。ビルド対象はmacOS 14です。実際に確認したOS・ツールのバージョンは検証記録を参照してください。

```sh
swift test
python3 scripts/check-localization.py
scripts/build-local.sh release
open "build/release/Galmuri.app"
```

スクリプトは識別子`forked.galmuri.local.release`のローカルReleaseをad-hoc署名で作成します。Debugは既存の`forked.galmuri.local`、別の保存先、青いDEVアイコンを使用します。ビルドだけではApplicationsへのインストールやAppleチーム登録は行いません。初回起動時はChromeへの接続画面を表示し、合成データは明示的なQA・サンプル実行時のみ作成します。隔離した作業領域、保存先、ネイティブ画面の確認方法は[ローカル開発](docs/local-development.md)を参照してください。実際の原本をテストデータに使わないでください。

## 反映の流れ

APIエディタではChromeを起動したまま、現在のAPIモデルを読み直してBase/Ours/Theirsをマージし、競合解決と最終承認の後に各操作を検証しながら反映します。削除対象の原本は見える復旧フォルダに移動します。結果が不確かな操作は再実行を止め、明示的に確認します。内容と構造の復旧であり、原子性や同期の保証はありません。実ユーザープロファイルへのAPI書き込みは引き続き制限しています。

既存のファイル方式の検証目標は次のとおりです。

1. 最初のスナップショットBaseを保持し、作業コピーOursを編集します。編集中もChromeを使用できます。
2. 反映前にブラウザでの作業を終え、Chromeを終了します。強制終了はしません。
3. 最新の原本Theirsを再読み込みし、3-wayマージと競合解決を行います。
4. 削除を含む変更を確認し、原本バックアップを検証した後、原本を再確認して置換します。
5. ファイル検証、Chrome再起動、同期の結果を区別し、復元手段を維持します。

これは全体の検証目標であり、現時点で実プロファイルへの書き込みをサポートするという意味ではありません。Egoへの直接対応は未定です。

フォルダの移動には戻る・進む・上のフォルダと、クリックできる階層パスを使えます。フォルダをブックマークリンクより先に表示し、種類も明示します。通常は直下の項目、検索時は下位フォルダも表示します。表示のグループ化は保存順序を変更せず、明示的な並べ替えは同じ種類の兄弟項目間で行います。

操作の取り消し履歴はアプリ終了時に消えます。再起動後も「未反映の変更」→「すべての変更を破棄…」で前後の内容を確認し、現在のプロファイルをGalmuriに保存された元の状態に戻せます。削除項目を復元し、追加・編集・移動・並び順の変更を取り消します。Chromeの再読み込みや書き込み、他のプロファイルの変更は行いません。

プロファイル管理では実データ・サンプルの保存済み項目を整理できます。削除前にワークスペースを非公開ローカルJSONに保存し、ブラウザのファイルと元データのバックアップを保持します。更新は平文を読み込み、3-way統合を確認してGalmuriのみを更新します。以前の作業を保存し、基準の元データが変わるため承認後に取り消し履歴をリセットします。選択した変更の取り消しと削除項目ごとの復元は影響範囲を先に表示します。HTTP・HTTPSブックマークは明示的な操作で既定のブラウザに開きます。元データの直接書き込みや実行中のブラウザの最新状態を保証するものではありません。
