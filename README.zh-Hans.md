# Galmuri · 갈무리

**在一处整理多个配置文件的书签，再应用回浏览器。**

[English](README.md) · [한국어](README.ko.md) · [日本語](README.ja.md) · 简体中文

Galmuri 是开发中的 **SwiftUI 原生 macOS 书签编辑器**。它将多个 Chrome 配置文件导入持久化工作副本，合并应用中的编辑与最新原始数据，然后供用户检查。现有文件方式的工作副本无需扩展程序。可选的配置文件扩展桥接现可读取正在运行的 Chrome 模型，并提供持久化编辑、三方检查，以及在明确启用的专用测试环境中可恢复的应用更改。

## 当前状态

通过设置 → 实验室 → API 连接与编辑器进行 API 操作和配置文件批准。扩展安装说明可保存匹配的 ZIP，`Bridge/extension` 中也已准备未来 GitHub 下载用的 Release 文件夹。直接文件写入也移入实验室，仅支持应用自有的合成测试文件。退出 Chrome 不会自动应用更改。参阅[实验室与安装](docs/labs.md)。扩展使用 `bookmarks`、`nativeMessaging` 和 `storage` 权限，不要求网站权限。普通连接对 Chrome 保持只读，仅明确标记的专用测试连接可以应用更改。已在专用 Chrome for Testing 中验证创建、重命名、移动、排序、移至恢复文件夹的删除、检查后恢复、中断状态采纳和正常重启。请参阅[API 配置、行为与限制](docs/chrome-api-workspace.md)。

Release27 修复了较大的进度与结果传输，增加停止确认、当前状态恢复、后退/前进/上级导航、多选与拖动目标。界面采用平静的灰色表面和蓝色操作及选择标记。Core 合并性能测量与限制见[原生界面改进](docs/native-refinement.md)。真实用户写入、实际无障碍操作、真实 Chrome 安装与同步验证仍受限制。

Release28 在待应用更改列表中显示待删除项目和文件夹内容更改，并支持确认后恢复。连接详情改用独立面板，保留已保存的编辑和工作副本兼容性。

Release30 增加独立且默认关闭的实验室开关。启用 API 编辑后，仅检查所选配置文件磁盘上的扩展安装记录，启用和连接状态仍需另行确认。更改检查现比较已保存源数据与工作副本，刷新合并保持独立。关闭功能会保留编辑，真实配置文件写入限制不变。

Release31 在主侧栏和首次连接页面增加设置入口，设置内分为通用与实验室。启用 API 编辑会检查一次 Galmuri 已登记的所有配置文件，此后手动重查。逐项显示记录和检查时间，切换编辑器选择不会自动重查。不会发现未登记的配置文件，安装记录仍与启用及连接状态区分。

Release32 落实了一次代码全面检查的结果。HTML 导出会跳过非 http(s) 地址并提示数量，不再整体失败；此类书签也可以改名。API 编辑会规范化已修改的地址，按显示顺序移动，只保留一个恢复记录，会话即将过期时不再开始应用，并删除已完成的任务文件。编辑时不再重新读取所有原始文件，未产生变化的编辑不会保存。撤销保留 100 步，“刷新前”存档副本只保留最新 10 份；“已断开”和“导入前”存档副本不会被自动删除。

Release33 完成了代码检查的后续工作。检查时的读取、合并、应用和恢复都在主线程之外运行，进行中无法通过关闭面板中断，恢复会说明是否真正完成。API 编辑会以与 Chrome 相同的形式保存已修改的地址（包括国际化域名），并拒绝 Chrome 会改写的地址；会话剩余不足两分钟或已保存地址不是 Chrome 形式时，会在开始前拒绝应用。未接入的加密存储实验代码已删除，主表格不再产生 AppKit 重入警告。

正在进行原生应用的本地开发。已实现侧边栏与表格、嵌套文件夹、书签编辑、多选移动和同配置文件内拖动、排序、搜索、相同 URL 视图、排除与撤销、工作副本 JSON 备份与导入，以及全部或文件夹范围的 Netscape HTML 导出。实际的 Swift 三方合并结果用于冲突选择与最终检查。目前原始备份、替换和恢复 **仅限应用创建的合成测试文件**。

通过文件方式连接的外部 Chrome 配置文件在原始位置保持只读。即使失去文件夹访问权限，工作副本仍可编辑；重新选择原文件夹可恢复访问，不会重置编辑。应用和恢复的确认同时绑定原始字节与文件标识；损坏记录不会隐藏有效备份。**加密书签支持已暂缓。** 设置 → 实验室仅显示关闭且不可用的“计划支持”项；不实现钥匙串访问或加密存储的应用集成。与应用分离的核心实验源码已于 2026-11-12 移除，[历史验证记录](docs/encrypted-store-adapter.md)仍然保留；该实验从未作为应用支持的功能。外部文件的直接写入仍未启用，上述独立受限的 API 测试不会解除此限制。明文存储权限与浏览器退出检测、浏览器采用更改与同步、原生辅助功能与语言以及分发验证仍未完成。直接应用更改是产品目标，HTML 导出不能替代它。相同 URL 的书签仍作为独立项目保留。

新工作区从浏览器连接界面启动。点击连接 Chrome 后，先尝试以普通权限访问默认位置；允许读取时直接显示配置文件名称。仅在需要授权或使用其他位置时，通过应用内提示选择文件夹。仅添加所选且受支持的配置文件。以前的测试配置文件和编辑内容均保留，可单独打开。界面提供可见的编辑、移动、删除和撤销控件，以及每行的铅笔按钮。单个书签删除后可立即撤销；删除文件夹或多个项目时，先显示目标和全部影响范围。请参阅[编辑体验决策](docs/editing-ux.md)。

GitHub 公开与正式发布推迟到本地检查之后。[TASKS.md](TASKS.md)记录进度与阻碍，[验证记录](docs/validation.md)记录证据和限制。

连接界面可选择 Chrome 或 Ego Lite，然后查找相应浏览器的默认位置。Ego Lite 是仅限明文书签的实验性只读连接，数据时效性及实际浏览器兼容性尚未验证。文件夹选择仅用于授权或自定义位置的备用流程，macOS 仍可能要求系统批准。

浏览器访问被拒绝时，首先显示文件夹授权指引。标准选择窗口会预先打开数据文件夹，请保留此位置并点击“允许访问此文件夹”。确认后读取配置文件信息，仅在成功时继续。对于适用macOS上的Chrome，只有确认文件夹后仍被拒绝才引导至系统设置；普通文件权限错误单独处理。现有工作保持不变。实际保护文件夹授权和权限持久性仍未验证。

收到指针仍可移动但点击和键盘输入无响应的报告后，已撤回自动查找设置项目。Release 17移除了辅助功能实现和权限请求，不再采用这一方式。系统设置指引中的按钮仅打开“文件与文件夹”，请手动查找并展开Galmuri。连接无需额外的辅助功能或自动化权限。该问题的原因仍未确定。

配置文件选择界面会列出检测到的书签文件及修改时间。即使存在加密或其他存储文件，仍可选择可读取的明文Bookmarks，其他文件内容会被排除。分别显示无明文文件和明文不可读，并提供原因。类型按名称分类，修改时间不能证明是Chrome的最新内容。所选明文会在导入时验证，原始文件写入限制保持不变。

## 本地运行

需要 macOS、Xcode 命令行工具及 Swift 6 或更新版本。构建目标为 macOS 14；实际验证的系统与工具版本见验证记录。

```sh
swift test
python3 scripts/check-localization.py
scripts/build-local.sh release
open "build/release/Galmuri.app"
```

脚本生成标识符为 `forked.galmuri.local.release`、ad-hoc 签名的本地 Release。Debug 保留 `forked.galmuri.local`，使用独立数据目录和蓝色 DEV 图标。仅构建不会安装到 Applications，也不注册 Apple 团队。首次启动显示 Chrome 连接界面；仅在显式 QA 或示例模式下创建合成数据。隔离工作区、数据位置和原生画面检查方法见[本地开发](docs/local-development.md)。请勿将真实原始数据用作测试资料。

## 应用流程

API 编辑器保持 Chrome 运行：重新读取实时 API 模型，合并 Base/Ours/Theirs，解决冲突并确认最终目标，然后逐项应用并验证。删除的原始项目移到可见的恢复文件夹；结果不确定时阻止重试，要求明确检查。这是内容与结构的恢复，不保证原子性或同步。真实用户配置文件的 API 写入仍受限制。

原有文件方式的验证目标如下。

1. 保留初始快照 Base，编辑工作副本 Ours。编辑期间可继续使用 Chrome。
2. 应用前完成浏览器工作并退出 Chrome。应用不会强制退出浏览器。
3. 重新读取最新原始数据 Theirs，执行三方合并并解决冲突。
4. 检查包括删除在内的全部更改，验证原始备份，再次检查原始数据后替换。
5. 区分文件验证、Chrome 重启和同步结果，并保留恢复途径。

完整浏览器流程是验证目标，并不表示当前支持写入真实配置文件。Ego 直接支持尚未决定。

## 语言与设计

英语为标准版本。包含韩语（`ko`）、日语（`ja`）和简体中文（`zh-Hans`）原生资源，已在本地基本检查语言选择和英语回退。翻译审校、完整的无障碍及布局检查、详细诊断翻译仍未完成。见[本地化政策](docs/localization.md)。繁体中文不在初期范围内。

[独立 HTML 设计原型](design/galmuri-prototype.html)使用合成数据，重新加载会重置。它是设计参考，并非原生运行时。原型单独测试：

```sh
node --test design/prototype.test.mjs
```

文件夹浏览支持后退、前进、上一级和可点击的路径。文件夹优先于书签链接显示，并标明类型；普通浏览只显示直接子项，搜索包含后代项目。显示分组不改变存储顺序；显式排序在同一父级、同类型的项目之间进行。

撤销历史在退出应用时清除。重新启动后，仍可通过“待处理更改”→“放弃所有更改…”查看前后差异，将当前配置文件恢复到 Galmuri 中保存的原始状态。这会恢复已删除项目，并取消新增、编辑、移动和排序更改。不会重新读取或写入 Chrome，也不会影响其他配置文件。

配置文件管理可整理已保存的真实或示例配置文件。移除前将工作区保存为私有本地 JSON，保留浏览器文件和原始备份。刷新会读取明文并检查三方合并，仅更新 Galmuri。确认后保存旧工作区并更新基准快照，同时清空撤销历史。撤销所选更改和逐项恢复已删除项目都会先显示完整影响。HTTP、HTTPS 书签仅在明确操作时通过默认浏览器打开。这些功能不会启用原始文件写入，也不保证正在运行的浏览器中的最新状态。
